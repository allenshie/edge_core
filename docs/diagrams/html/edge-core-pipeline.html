3. Pipeline flow
先看共享狀態，再看 stage 順序

這個版本把 flowchart 拆成兩層。上層是 shared resources，講清楚誰會寫進 TaskContext； 下層才是 pipeline 三大區塊，讓 data flow 與 control flow 不會互相干擾。

TaskContext rail. frame_meta 由 ingestion 寫入後往下游傳遞； edge_mode 與 matching_result_snapshot 來自 backend updates， 會被 inference 與 streaming 讀取。

Quick read
這張圖的重點

frame_meta 是主幹

它從 ingestion 往下游流，讓 inference 與後續輸出都能看到同一份 frame context。

edge_mode 是控制訊號

它不是 frame 本身，而是 runtime 的模式開關，會影響 inference 與 streaming 的行為。

stream 與 publish 分流

視覺輸出與事件發布各自有出口，這也是 pipeline 設計上最重要的分界。
